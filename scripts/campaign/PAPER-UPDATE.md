# Updating Paper and Report from Lab Campaign Bundle

This guide explains how to update the evaluation sections of the paper and technical report using only the contents of the collected lab bundle (the `lab-bundle` folder). No git repository access or internet connection is required.

---

## 1. Bundle Contents

The bundle contains everything needed for the publication update:
- `analysis.txt`: Summary tables, medians, 95% bootstrap confidence intervals, speedup ratios, and verdicts generated by `analyse.py`.
- `figures/`: Rendered PNG and PDF charts (e.g. scaling curves, cache timing).
- `results/lab/`: Raw measurement logs and `runs.jsonl` records.
- `docs/paper/paper.tex`: Conference paper LaTeX source.
- `docs/paper/journal/manuscript.tex`: Journal manuscript LaTeX source.
- `docs/report/*.tex`: Technical report LaTeX source (including `results.tex`).
- `docs/benchmarks/campaign-cases.md`: Benchmark case handling and methodology specification.
- `scripts/campaign/experiments.tsv`: Complete experiment definitions.
- `source.txt`: Git commit hash and tree status when the lab was executed.
- `MANIFEST.sha256`: SHA-256 checksums verifying bundle file integrity.

---

## 2. Human Workflow

1. **Verify Integrity**:
   ```bash
   sha256sum -c MANIFEST.sha256
   ```
2. **Review Analysis**:
   Open `analysis.txt` and review the summary tables for each experiment (`E1`, `E4`, `E5`, `E6`, `E7`, `E8`, `E11`, `E13`, `E14`, `E15`, `E16`, `E17`, `E18`, `E19`, `E20`).
3. **Copy Figures**:
   Copy figures from `figures/` to the figure directory specified in each LaTeX document (e.g. `docs/paper/` or `docs/report/figures/`).
4. **Update LaTeX Files**:
   Update numbers, tables, and discussions in `docs/paper/paper.tex`, `docs/paper/journal/manuscript.tex`, and `docs/report/results.tex` according to the mapping table below.
5. **Compile & Check**:
   Recompile LaTeX documents with `pdflatex` or `latexmk` and inspect tables and figures.

## 4. Strict Publication Rules

Follow these rules unconditionally when updating the LaTeX documents:

1. **Every Number Grounded**: Every timing, ratio, speedup, and metric must come directly from `analysis.txt` or `results/lab/runs.jsonl`.
2. **Never Invent Data**: Do not extrapolate, extrapolate unmeasured values, or invent data points.
3. **Report Missing Measurements Honestly**: If an experiment or size was not measured or produced invalid runs, state explicitly that it was not measured (e.g., "not measured" or omitted from table).
4. **Label Emulated Results**: Any result obtained under container emulation or rate shaping (`tc netem`, quota containers) must be explicitly identified as *emulated*.
5. **Publication-Level Prose**: Maintain rigorous, objective, academic language suitable for IEEE/ACM transactions and conferences.
6. **No Development History**: Omit engineering trivia, bug fixes, refactoring iterations, git commit history, and prompt/brief references.
7. **No Check Tallies**: Do not state test counts, check counts, or testing checklists (e.g. avoid "passed 45 checks").
8. **Leave Author Details**: Do not modify author names, affiliations, email addresses, or acknowledgements.

```text
  - `docs/paper/journal/manuscript.tex`
  - `docs/report/results.tex`

### Rules

2. Do not invent, extrapolate, or estimate any numbers.
3. If a metric was not measured or is missing in the data, state clearly that it was not measured.

5. Use concise, publication-grade academic English.
6. Do not include project development history, debugging steps, or test tallies.
7. Preserve all author identities, affiliations, and acknowledgments unchanged.
8. Follow the mapping table in `PAPER-UPDATE.md` to place results in the correct sections.

Please output complete, ready-to-paste LaTeX diffs or updated sections for the requested files.
```
