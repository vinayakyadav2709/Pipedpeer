# W10 speedups: before and after

**Every number here is emulated.** The lab is equal containers (2 CPUs each,
same memory) with links shaped by tc netem, all on one host. Speedup is 1
container against N containers of the same size. It is never measured against
the 15-core host, and it is not a real-hardware number.

## Method

- BEFORE: the binary built from `c7e2c7f` (the pure-move split), kept in
  `~/.local/share/pipedpeer-bench/bin/`. AFTER: the tree under test.
- Rig: `scripts/lab-emu.sh`. Runner: `scripts/bench-lib.sh`. Driver:
  `scripts/bench-w10.sh`. The case table at the top of the driver gives every
  workload, profile and flag.
- Every case runs the same workload with the same flags on both binaries, so
  a changed default (int8 on, fp32 averaging) shows up as a user would see it.
  Only a renamed feature gets separate flags: diloco runs
  `PIPEDPEER_DDP_SYNC_EVERY=auto` on BEFORE and `--ddp-sync fast` on AFTER.
- Each workload is warmed once (environment built and shipped) before the
  timed runs. `cold` builds on a fresh lab for each repetition.
- Metrics, each the median of 3:
  - `wall`: the whole `pipedpeer run`, timed from outside.
  - `script`: the workload's own timed section.
  - For the training cases also `sync` (ddp_sync steps from steps.json, else
    the shim's line) and `loss` (validation loss).
- Groups:
  - pool: 3 nodes x 1.5g, plus a 1-node baseline (`n1`).
  - train: 2 x 2g, plus `n1`.
  - hub: 3 x 1.5g.
  - cold: 3 x 1.5g, a fresh lab per repetition.
- Every timed run holds `~/.cache/pipedpeer-bench.lock`.
- Lab artifact: `os.cpu_count()` inside a container reports the host's 16
  cores, not its 2-CPU quota. So `Pool()` starts 14 workers on 2 CPUs. Both
  binaries get the same, so the comparison stands, but the absolute times
  include that oversubscription.

```sh
scripts/bench-w10.sh before                    # BEFORE column
scripts/bench-w10.sh after                     # AFTER column (verify pass)
scripts/bench-w10.sh table                     # medians as markdown
CASES="poolsend zstd" scripts/bench-w10.sh after
```

Raw rows: `~/.local/state/pipedpeer/bench/w10/results.csv`, with logs beside it.

## Cases

| case | W10 item | workload | profile |
|---|---|---|---|
| int8 | int8 gradient sync on by default | train, 4.5 M params, `--ddp 2` | wifi |
| fp32avg | fp32 weight averaging for local SGD | train, SYNC_EVERY=8 | wifi |
| diloco | local SGD -> DiLoCo | train | wifi |
| overlap | overlap sync with backward | train, heavy step | lan |
| nohub | no single hub at 3+ ranks | train, `--ddp 3` | lan |
| chunksize | chunk size from transfer cost + RTT | 2000 tiny items | wifi |
| prefetch | per-node prefetch queue by RTT | 300 items | 5g |
| tail | one tail backup / per-node in-flight | 96 uneven items | wifi |
| poolsend | O(n) `_pool_send` body | 48 x 8 MB inputs | lan |
| fingerprint | function + big inputs once per peer | 32 MB shared argument | wifi |
| zstd | zstd level by link speed | 48 x 2 MB compressible | 5g |
| pickle5 | pickle-5 out-of-band numpy buffers | 48 x 8 MB float64 arrays | lan |
| linkcost | cost model on the measured link speed | 48 x 4 MB, cheap items | 5g |
| stats | stats across runs | repeated runs (rep 1 vs later) | wifi |
| noop | ms seed step, env-wrapper skip | empty script (wall = overhead) | lan |
| cold | cache.nixos.org fetch, closure ship | fresh lab | lan |
| (PERF-HUNT) | one row per finding | appended to the case table | |

Not in the lab:
- Multi-GPU fast path: needs a host with two GPUs, so it is a real-hardware
  check.
- GPU cases: single-GPU baselines only, on the real GPU
  (`bench-ddp-switch.sh --gpu-baseline`).

Row notes:
- diloco: no sync (B1 swallowed), so the ranks trained alone. c7e2c7f logs
  "torch interception unavailable: invalid literal for int() with base 10:
  'auto'" and carries on without the ring. These are not DiLoCo numbers.
- overlap: no ring formed. The coordinator said "fewer than 2 eligible nodes,
  running single-node" (world 1) under that load. It is not a ring number.
- int8: c7e2c7f syncs in fp16 by default. Sync was 60.1 s of the 77.1 s
  script on wifi.
- Missing: nohub (3 nodes), the one-node training baselines and cold. The
  memory cap stayed full of other labs for over an hour, so QUIET-RERUN fills
  them.
- Discarded: the first training rows, from a bench model that did not learn
  (SGD sat at ln 2 even on one device; train.py now uses Adam). They are kept
  in `~/.local/state/pipedpeer/bench/discarded/`.

QUIET-RERUN, idle host, for `before` and then `after`:

```sh
scripts/bench-w10.sh before   # all 30 runs; = ONLY="pool:n3 pool:n1 train:n2 train:n1 hub:n3 cold:n3"
scripts/bench-w10.sh after
BL_DRY=1 ONLY="..." scripts/bench-w10.sh after   # prints the labs and runs, runs nothing
```
